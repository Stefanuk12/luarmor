Luarmor uses [Luraph](https://luraph.com) as its obfuscation provider, so if you're experiencing lag, FPS drops or even crashes, you need to use certain [macros](/scripting/macros) in your script. This page explains how to use the `LPH_NO_VIRTUALIZE` macro.

<Note>
    If your code runs fine unobfuscated but lags or crashes once obfuscated, this page explains why and how to fix it.
</Note>

## Why does obfuscation affect performance?

[Luraph](https://luraph.com) is a VM-based obfuscator: it turns your code into its own custom instructions, which are run by Luraph's VM, which in turn is run by the Lua interpreter. This greatly increases the number of instruction cycles.

<Accordion title="How obfuscation works">
    Normally, your script gets compiled into a set of Lua instructions. See the example below:

    <CodeGroup>
        ```lua What you see
        print("hi", game)
        ```

        ```text What the Lua interpreter sees
        GETGLOBAL  0 -1    ; print
        LOADK      1 -2    ; "hi"
        GETGLOBAL  2 -3    ; game
        CALL       0 3 1
        ```
    </CodeGroup>

    As you can see, your simple `print` statement gets compiled into 4 instructions. Each instruction is a cycle, so it will take **4 cycles to execute your code**.

    When you obfuscate your script, the main goal is to make the original code unreadable. Luraph does this by generating its own custom instruction set that only the Luraph VM can understand.

    See the example below:

    <Frame caption="How Luraph obfuscates Lua code">
        <img src="/images/optimisation-2.png" alt="Side by side: a short piece of an obfuscated VM loop, and the 40 bytecode instructions it compiles to"/>
    </Frame>

    Notice how your simple `print` statement turned into 40 instructions, which will take **40 cycles to execute**. Also keep in mind that Luraph does a lot of things to obfuscate the code flow, which will ultimately lead to *even more instructions*.
</Accordion>

Normally, Lua is extremely fast, so you **will not notice** any performance impact. But when your code runs **hundreds of times per second**, there will be obvious lag, FPS drops or even freezes while those instructions run.

A good example is `RenderStepped` connections, which scripts often use to run their wallhack rendering every frame.

<Accordion title="RenderStepped example">
    <Frame caption="Example of a RenderStepped connection">
        <img src="/images/optimisation-3.png" alt="A RenderStepped connection that runs 60+ times a second and updates a tracer's render properties every frame"/>
    </Frame>

    This code will be slow when obfuscated, because the number of instructions generated by Luraph will be more than *2000*. This means Lua will have to run **2000+ instruction cycles every frame**, which is around **60 * 2000 = 120k** instructions every second.

    This loop also calls local functions (e.g. `CalculateParameters`), which run every frame as well, adding *even more instructions*.
</Accordion>

Here is a second example, a metamethod hook on `__index`:

<Accordion title="__index example">
    <Frame caption="Example of a metamethod hook">
        <img src="/images/optimisation-4.png" alt="An __index metamethod hook on game that runs every time any property is read, used here to redirect mouse targeting"/>
    </Frame>

    `__index` runs very often. For example, each of these invokes it:

    - `game.Workspace`
    - `game.Players`
    - and so on

    Each one runs the hook code above, which is extremely resource intensive because the hook is probably called **thousands of times per second**.

    On top of that, **if you obfuscate this part**, you will end up with **more than a million** instructions to run every second, which will crash your game.
</Accordion>

## How to deal with this problem?

<Warning>
    **Do not** wrap your entire script in `LPH_NO_VIRTUALIZE`, as it defeats the purpose of virtualization (obfuscation). Only use this macro if a function runs more than 30 times per second.
</Warning>

You need to exclude these frequently run functions from obfuscation, using either `loadstring()` or `LPH_NO_VIRTUALIZE`.

We recommend `LPH_NO_VIRTUALIZE` over `loadstring`, because code excluded with `LPH_NO_VIRTUALIZE` is generally harder to view.

## Where to use `LPH_NO_VIRTUALIZE`?

- `RenderStepped` connections
- `Heartbeat` connections
- `__index` metamethod hooks
- `__namecall` metamethod hooks (optional)
- `while true` loops with no delay
- GC scan loops
- Functions called by any of the above

## How to use `LPH_NO_VIRTUALIZE`?

`LPH_NO_VIRTUALIZE` takes one argument, which must be a constant function (written inline, not passed as a variable), and returns a function you can call.

<Warning>
    Add this at the top of your script, so the original (unobfuscated) code still runs:

    ```lua
    getfenv().LPH_NO_VIRTUALIZE = function(f) return f end;
    ```
</Warning>

This pattern works for any LPH macro. See [Macros](/scripting/macros).

Here are examples of good and bad usage of `LPH_NO_VIRTUALIZE`:

<AccordionGroup>
    <Accordion title="Good usage">
        ```lua
        RunService.RenderStepped(LPH_NO_VIRTUALIZE(function(s)
            -- regular function body
        end))
        ```

        ```lua
        old = hookmetamethod(game, "__index", LPH_NO_VIRTUALIZE(function(t, k)
            -- regular function body
        end))
        ```

        ```lua
        local generateTracers = LPH_NO_VIRTUALIZE(function(pos, pos2)
            -- function body
        end)
        RunService.Heartbeat:Connect(generateTracers)
        ```

        ```lua
        LPH_NO_VIRTUALIZE(function()
            for i,v in pairs(getgc()) do
                if type(v) == 'table' then
                    f = v
                end
            end
        end)()
        ```
    </Accordion>
    <Accordion title="Bad usage">
        ```lua
        local function doSomething()
        -- function body
        end
        LPH_NO_VIRTUALIZE(doSomething) -- you can't pass reference arguments
        hookfunction(print, doSomething)
        ```

        ```lua
        LPH_NO_VIRTUALIZE( -- this is a syntax error
            local old old = hookmetamethod(game, "__namecall", function(...) end)
        )
        ```

        ```lua
        LPH_NO_VIRTUALIZE(function()
            -- something
        end) -- This part will not run because you are not calling it at the end.
        -- You should add an extra () at the end in order to call it

        print('done')
        ```
    </Accordion>
</AccordionGroup>
