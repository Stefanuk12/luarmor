Luarmor has a Discord bot that you can invite to your server. It lets you manage your script, whitelist users and more, and lets users manage their own keys.

## Inviting the bot

<Warning>
    After inviting the bot, you must run `/login [API KEY]` within 15 minutes, or the bot will leave the server automatically. If the bot leaves before the 15 minutes are up, an anti-raid bot has probably removed it; check your audit logs for details.
</Warning>

<Frame caption="/login command">
    <img src="/images/discord-login-command.png" alt="The /login slash command in Discord with the api_key option filled in" />
</Frame>

All of the bot invite links are on the [bot invite page](https://luarmor.net/bot). The bots are identical; there are several because Discord limits the number of servers a single bot can be in.

## Setting up permissions

### Manager role

People with the manager role can run basic management commands like [`/whitelist`](#whitelisting-users) and [`/force-hwidreset`](#manager-commands). You choose this role when you [create a panel](#create-a-panel).

### Buyer role

<Note>
    This role is optional.
</Note>

This role is automatically assigned to users when:

- a manager whitelists them
- they redeem a key via the [panel](#create-a-panel)
- they click **Get Role** on the [panel](#create-a-panel)

It lets them get the script from the [panel](#create-a-panel) and reset their HWID. You can choose this role when you [create a panel](#create-a-panel).

### Advanced permissions

For fine-grained control over who can run which command, use Discord's built-in command permissions. Open **Server Settings > Integrations** and click **Manage** next to Luarmor.

<Steps>
    <Step title="Disable every command for the manager role">
        Make sure every Luarmor command is disabled for your manager role. This is the baseline: holding the manager role alone no longer gives access to any command.
    </Step>
    <Step title="Re-enable commands for higher roles">
        Create higher roles (for example, `Senior Manager` or `Admin`) and re-enable only the commands each role should be able to use. Give these roles to your staff alongside the manager role.
    </Step>
</Steps>

<Note>
    Members with Discord's **Administrator** permission can always use every command, whatever these settings say.
</Note>

## Create a panel

<Warning>
    You can only have one panel per project. If you want one panel to load multiple games, consider writing your own loader that does this. To group scripts under one project, see [Creating a project](/quickstart#creating-a-project).
</Warning>

<Steps>
    <Step title="Create the loader script">
        This is the script users receive when they press **Get Script** on the panel, which you create in the next step. It is usually your [Luarmor loader](/quickstart#download-the-loader). The bot sends it with the user's `script_key` added on top.

        For example, a `loader_script` file could contain just:

        ```lua
        loadstring(game:HttpGet("https://raw.githubusercontent.com/something/blabla.txt"))()
        ```

        <Warning>
            Keep your loader script short, because Discord limits the size of files the bot can send. If your script is too large, upload it manually to a `#script` channel instead and make the `loader_script` point users to that channel.
        </Warning>
    </Step>
    <Step title="Create the panel">
        Run the `/setpanel` command to create a panel in the current channel. It requires a `loader_script` and a `manager_role`, and optionally takes a `buyer_role`. For how the **Redeem Key** and **Reset HWID** buttons work with keys, see [Create User/Key](/api-reference/endpoint/user-management/create-userkey#basics).

        <Frame caption="An example panel">
            <img src="/images/example-panel.png" alt="The Luarmor control panel message in Discord with Redeem Key, Get Script, Get Role, Reset HWID and Get Stats buttons" />
        </Frame>
    </Step>
</Steps>

## Whitelisting users

[Managers](#manager-role) can whitelist and unwhitelist users with the `/whitelist` and `/unwhitelist` commands.

<Note>
    If you don't specify `days`, the user is whitelisted indefinitely. See also [expiry dates and time-limited keys](/api-reference/endpoint/user-management/create-userkey#expiry-dates-and-time-limited-keys).
</Note>

<Accordion title="Mass whitelist">
    <Warning>
        This command is disabled for the foreseeable future.
    </Warning>

    If you already have users with a specific role, you can whitelist all of them at once with the `/mass-whitelist` command. It asks for the `role` and, optionally, the number of `days`.

    In the result, `Total failed` counts users whose Discord IDs were already registered. They are skipped to avoid duplicate entries.

## Luarmor logs

The `/setlogs` command logs all Luarmor command and button usage in your server to a [Discord webhook](https://support.discord.com/hc/en-us/articles/228383668-Intro-to-Webhooks).

## Manager commands

Only people with the [manager role](#manager-role) can run these commands.

| Command | What it does |
|---------|--------------|
| `/blacklist` | Blacklists a specific Discord user from the project. You can optionally give a reason, which is shown to the user, and a number of `days`. If `days` is not provided, the user is blacklisted indefinitely. To unban, use [Unban User](/api-reference/endpoint/user-management/unban-user). |
| `/compensate` | Adds a specified number of days to everyone's keys in the project, for example when your script was patched and you want to compensate your users. If it fails, see [Failed to compensate](/troubleshooting/script-owners#discord-bot). |
| `/force-hwidreset` | Resets a specific user's HWID, ignoring any cooldown you have set. The API equivalent is [Reset User HWID](/api-reference/endpoint/user-management/reset-user-hwid) with `force`. |
| `/login` | See [Inviting the bot](#inviting-the-bot). |
| `/logout` | Logs the bot out of the server. |
| `/mass-whitelist` | See [Whitelisting users](#whitelisting-users). |
| `/setlogs` | See [Luarmor logs](#luarmor-logs). |
| `/unwhitelist` | See [Whitelisting users](#whitelisting-users). |
| `/whitelist` | See [Whitelisting users](#whitelisting-users). |

Having problems? See [Discord bot troubleshooting](/troubleshooting/script-owners#discord-bot).
